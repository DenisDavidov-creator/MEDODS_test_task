# Task Service

Сервис для управления задачами с HTTP API на Go.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Чистый запуск контейнера (с down -v)

```bash
make up-clean
```

## Очистка смотрированного sql и остановка containers
```bash
make down 
```

## What to do 

    Нужно реализовать возможность создавать итеративные задачи
    - каждый n-й день 
    - определенное число каждого месяца 
    - конктретные даты
    - только четные или нечетные дни месяца

## How to do 

1) Создать поля периодичности в самом task
2) Создать отдельную таблицу, task_recurrence в которой уже будут выбраны периодичности 
3) Создание task_tamplate на основе которых создаются таски. (Наверное самый удобный, но пораждает слишком много доп. вопросов)

## My choice
    Почему не 1 вариант: поля периодичности, в большинстве случаев будут null, плюс сама задача не обязательно должна следовать какой-то периодичности

    Почему не 3 вариант: Это больше подходит как дополнительная фича, выбор не периодичности, а шаблона, в будущем можно добавить как отдельное дополнение, плюс пораждает слишком много вопросов, что делать в тех или иных случаях

    Почему 2 вариант: Сохраняет изначальную таблицу task неизменной, связь опциональная, легко масштабировать

## Допущения

| Решение | Граничный случай | Поведение |
|---|---|---|
| `day_of_month` от 1 до 31 | `day_of_month=31` в феврале | → 28/29 февраля (последний день месяца). Задача не пропускает месяц |
| `specific_dates` — хотя бы одна дата в будущем | Все даты в прошлом | Валидация отклоняет запрос; прошедшие даты внутри списка игнорируются при вычислении `next_run_at` |
| При обновлении периодичность перезаписывается целиком | `recurrence == currentRecurrence` | UPDATE выполняется с теми же значениями. |
| `GetByTaskID` — второй запрос только для `specific_dates` | Тип `interval` / `even_odd` / `day_of_month` | Запрос за датами пропускается — один запрос вместо двух |
| `GetByID` — два запроса; `List` — JOIN | `List` с N задачами | `ListByTaskIDs` с `ANY($1)` и LEFT JOIN — один запрос на все задачи, без N+1 |
| Воркер раз в час | БД была недоступна несколько часов | `next_run_at <= now` поймает пропущенные записи при следующем тике |
| Воркер не наверстывает пропуски | Сервис не работал 3 дня | Создаётся один экземпляр задачи, а не по одному за каждый день |
| `interval` > 0 | `interval = 0` | Валидация отклоняет|
| `even_odd` — по числу месяца | `even` в день 15 | 15 — нечётное → пропускается; следующий запуск на 16-е |

## Реализация

### Схема БД

Две новые таблицы:
- `recurrence` — настройки периодичности, связана с `tasks` через `task_id` (`ON DELETE CASCADE`)
- `recurrence_dates` — конкретные даты для типа `specific_dates`, связана с `recurrence` через `recurrence_id` (`ON DELETE CASCADE`)

### Архитектура

Два репозитория (`TaskRepository`, `RecurrenceRepository`) — один сервис (`TaskService`). Репозитории разделены, потому что отвечают за разные таблицы и не знают друг о друге. Сервис один, потому что операции над задачей и периодичностью неотделимы с точки зрения бизнес-логики — создание/обновление задачи с периодичностью должно быть атомарным.

### Воркер

Фоновая горутина запускается раз в час и вызывает `ProcessDue`:
1. Находит все записи `recurrence` где `next_run_at <= now`
2. Для каждой создаёт новую задачу-экземпляр
3. Вычисляет следующую дату и обновляет `next_run_at`
4. Если следующей даты нет (`specific_dates` закончились) — удаляет `recurrence`

Ошибка при обработке одной записи логируется и не останавливает обработку остальных.

### Транзакции

Создание и обновление задачи с периодичностью выполняется в транзакции — изменения в `tasks` и `recurrence` атомарны. Реализовано через паттерн **Unit of Work** (`Transactor`): транзакция передаётся через `context`, репозитории достают её через `getQuerier`.

### Swagger

Документация доступна по адресу `http://localhost:8080/swagger/` после запуска сервиса.

### Тесты

Покрыта функция `calculateNextRunAt` — ключевая бизнес-логика вычисления следующей даты для всех типов периодичности, включая граничные случаи.

## Примеры запросов

Swagger доступен по адресу `http://localhost:8080/swagger/` — там можно выполнить запросы напрямую через UI.

**`POST /tasks` — каждые N дней (`interval`)**
```json
{
  "title": "Осмотр",
  "description": "Плановый осмотр",
  "status": "open",
  "recurrence": {
    "type": "interval",
    "interval": 3
  }
}
```

**`POST /tasks` — определённое число каждого месяца (`day_of_month`)**
```json
{
  "title": "Отчёт",
  "description": "",
  "status": "open",
  "recurrence": {
    "type": "day_of_month",
    "day_of_month": 15
  }
}
```

**`POST /tasks` — чётные или нечётные числа (`even_odd`)**
```json
{
  "title": "Обход",
  "description": "",
  "status": "open",
  "recurrence": {
    "type": "even_odd",
    "even_odd": "even"
  }
}
```

**`POST /tasks` — конкретные даты (`specific_dates`)**
```json
{
  "title": "Конференция",
  "description": "",
  "status": "open",
  "recurrence": {
    "type": "specific_dates",
    "specific_dates": ["2025-06-01T00:00:00Z", "2025-09-01T00:00:00Z"]
  }
}
```

**`POST /tasks` — без периодичности**
```json
{
  "title": "Разовая задача",
  "description": "",
  "status": "open"
}
```
